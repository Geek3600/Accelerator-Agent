# SpatialAccAgent 论文问题定义与问题价值论证文档

## 0. 文档目的

本文档用于明确 SpatialAccAgent 论文的核心问题定义、研究边界、问题价值和审稿人说服逻辑。本文档的目标不是描述完整方法细节，而是回答以下几个决定论文水平的根本问题：

1. 我们到底解决什么问题？
2. 这个问题为什么不是已有工作已经解决的？
3. 这个问题为什么重要，为什么值得 DAC 论文关注？
4. 我们应该如何向审稿人证明这个问题真实存在、代价高、具有普遍性？
5. 我们的方法为什么能够针对性解决这个问题？

当前暂定题目为：

**SpatialAccAgent: Constraint-Guided Agentic Design Closure for LLM Spatial Accelerators**

本文档建议将论文的核心问题定义为：

**Cross-Layer Consistency Problem in Agentic LLM Spatial Accelerator Design**

即：

**面向 agentic LLM spatial accelerator 设计的跨层一致性问题。**

---

## 1. 一句话问题定义

SpatialAccAgent 解决的不是“LLM agent 能不能生成 RTL / Chisel / HLS”这一类局部 artifact generation 问题，也不是“agent 能不能跑完整硬件设计流程”的 feasibility 问题，而是：

**当 LLM agent 参与 decoder-only LLM spatial accelerator 的长流程设计时，如何在模型语义、空间流水、Chisel/RTL、stream protocol、DDR/AXI layout、runtime configuration、verification trace、synthesis/P&R evidence 之间维护显式的跨层一致性，使局部生成的 artifact 最终能够组合成全局正确、可验证、可部署、可修复、QoR 可信的 accelerator design package。**

更精炼地说：

**The next bottleneck of agentic accelerator design is not whether an LLM agent can generate hardware artifacts, but whether it can maintain global consistency among those artifacts so that the resulting accelerator is functionally correct, deployable, repairable, and QoR-credible.**

中文表述：

**agentic accelerator design 的下一阶段瓶颈，不再是 LLM agent 能不能生成硬件 artifact，而是它能不能在这些 artifact 之间维护全局一致性，从而让最终加速器在功能上正确、系统上可部署、错误上可修复、性能上可信。**

---

## 2. 问题边界：我们不是在解决什么？

为了避免被已有工作打穿，论文必须清晰说明我们的研究边界。

### 2.1 我们不是解决“LLM 能不能生成 RTL”

已有工作已经大量探索了 LLM 生成 Verilog、SystemVerilog、HLS、testbench、EDA script 的能力。它们通常关注：

* 如何从自然语言生成 RTL；
* 如何提高 RTL functional correctness；
* 如何让 LLM 通过 testbench/debug loop 修语法和功能错误；
* 如何让 LLM 生成 PPA-aware RTL；
* 如何通过 multi-agent 协作提高代码质量和可解释性。

这些工作证明了 LLM 参与硬件代码生成是可行的，但它们主要关注的是 **local artifact generation quality**。

SpatialAccAgent 的核心不是让 LLM 写出某一段 RTL，而是让 agent 在生成多个互相依赖的 artifact 时，始终知道这些 artifact 共享哪些设计约束，并在出错时能够定位是哪一层约束被破坏。

因此，我们的定位不是：

**Can LLMs generate RTL?**

而是：

**Can LLM agents maintain a globally consistent design state across the accelerator design flow?**

---

### 2.2 我们不是解决“如何从 PyTorch 编译出 dataflow accelerator”

已有 accelerator compiler 和 ADL 工作已经能从结构化程序或 IR 出发，生成高性能 spatial/dataflow accelerator。它们通常关注：

* kernel-level optimization；
* multi-kernel composition；
* stream layout；
* FIFO sizing；
* kernel fusion；
* memory allocation；
* resource allocation；
* HLS/backend codegen；
* runtime generation。

这些工作证明 spatial accelerator 本身需要结构化 IR、type system、stream representation 和 dataflow analysis。

但是它们的输入通常已经是结构化 program / compiler IR。它们主要解决的是：

**structured accelerator compilation problem**

而 SpatialAccAgent 解决的是：

**agentic design closure problem across heterogeneous artifacts**

也就是说，我们的问题从更早开始，也结束得更晚：

* 更早：从模型配置、论文/文档、量化说明、模板库、平台约束中抽取设计约束；
* 更晚：一直维护到 Chisel/RTL、trace、DDR image、AXI wrapper、host runtime、EDA report、repair log 和 board evidence。

因此，我们不是替代 Allo / StreamTensor 这类 compiler，而是解决 agentic design 中 compiler IR 之外的跨 artifact 一致性维护问题。

---

### 2.3 我们不是解决“agent 能不能端到端做芯片”

已有 long-horizon chip agent 工作已经展示 agent 可以完成非常长的硬件设计流程，包括 architecture planning、RTL implementation、verification、synthesis、P&R、timing closure 甚至 FPGA/ASIC mapping。

这说明：

**long-flow execution is becoming feasible.**

但这并不意味着 agentic hardware design 已经真正可靠。对于复杂 accelerator 而言，agent 需要维护大量跨阶段共享约束。一旦缺少显式 design state，agent 就可能出现以下问题：

* 局部模块测试通过，但 top-level 连接后错误；
* stage-level 数值正确，但 system-level DDR image 接入后输出 garbage；
* agent 看到 numeric mismatch，却无法判断是合理量化误差还是硬件 bug；
* agent 看到 timing violation，却无法判断应该改 backend script 还是 RTL pipeline；
* agent 为了修 timing 加 register，却破坏 valid alignment 或 residual bypass；
* agent 修复一个局部 bug 后，引入新的 regression failure。

因此，我们不是证明 agent 能不能做完整流程，而是解决：

**How can long-horizon hardware agents maintain cross-stage consistency and perform trustworthy design closure?**

---

## 3. 核心问题：Cross-Layer Consistency Problem

### 3.1 什么是 cross-layer consistency？

一个 decoder-only Transformer block 从 HuggingFace / PyTorch 到 FPGA spatial accelerator，会经历多次语义下降和 artifact 生成：

1. Model configuration / HuggingFace module
2. Operator-level block semantics
3. Quantization and numeric policy
4. Tiled spatial pipeline plan
5. Processing-unit partition
6. Chisel modules
7. RTL / SystemVerilog
8. Stream interconnect
9. DDR image layout
10. AXI wrapper
11. Host runtime
12. Stage-level verification
13. Top-level verification
14. System-level simulation
15. Synthesis / implementation / timing closure
16. Board-level execution and benchmark

每一层都会生成新的 artifact，但这些 artifact 不是孤立的。它们共享同一组设计约束。例如：

* hidden size、head number、KV-head number、head dimension；
* Q/K/V projection shape；
* RoPE dimension layout；
* GQA query-head to KV-head mapping；
* RMSNorm / LayerNorm 的数值行为；
* W8A8 / W4A8 quantization scale layout；
* stream token/head/tile/lane/beat order；
* ready/valid、last、strobe、beat count；
* DDR base address、stride、burst、bank、packing；
* runtime buffer map；
* FIFO depth、producer-consumer rate、bounded liveness；
* pipeline stage latency、valid alignment、residual bypass；
* synthesis timing target、resource budget、routing constraints。

所谓 **cross-layer consistency**，就是这些约束在不同设计层、不同 artifact、不同验证阶段之间必须保持一致。

---

### 3.2 为什么这个问题在 LLM spatial accelerator 中尤其严重？

LLM spatial accelerator 同时具有三类复杂性。

第一，模型语义复杂。不同 decoder-only LLM block 的结构差异明显，例如：

* GPT/OPT-style：LayerNorm、MHA、GELU；
* LLaMA-style：RMSNorm、RoPE、SwiGLU；
* Qwen-style：RMSNorm、RoPE、GQA、SwiGLU；
* Gemma-style：不同 attention head / KV-head 配置；
* 量化版本还会引入 scale、zero-point、rounding、saturation、packing 等数值约束。

第二，spatial accelerator 的执行方式复杂。它不是 GPU 上的顺序 kernel 调用，而是多个 processing unit 通过 streaming、FIFO、layout converter、DMA、AXI 连接起来形成空间流水。局部模块正确不等于全局 streaming schedule 正确。

第三，agentic design flow 本身复杂。agent 会生成不同类型的 artifact，包括文档、架构计划、Chisel、RTL、testbench、trace、DDR image、runtime、TCL script、EDA report、repair patch。普通自然语言上下文很难稳定维护这些 artifact 之间的精确关系。

因此，agent 在每个阶段都可能生成看似正确的 artifact，但缺少一个显式的全局设计状态来维护跨阶段共享约束。结果是：

**局部 artifact 可以分别通过检查，但它们组合后可能违反模型语义、数值策略、stream 协议、memory layout、runtime 配置或 backend 假设，导致系统级错误、QoR 退化、调试困难和修复不稳定。**

---

## 4. 这个问题的具体表现

我们要把问题严重性从“设计出来的加速器可能不是很好”强化为：

**局部正确、全局错误；局部可跑、系统不可部署；局部优化、全局 QoR 退化；局部修复、引入新 bug。**

### 4.1 局部正确，全局错误

单个 processing unit 可能通过 stage-level verification，但 top-level 或 system-level 输出错误。

示例：

QKV GEMM stage-level 正确，RoPE stage-level 正确，attention score stage-level 正确，但 Qwen-style GQA 的 query-head 到 KV-head mapping 在 stream schedule 和 KV memory layout 中不一致，导致 top-level attention 输出错误。

这不是某个 GEMM 模块错了，而是 model semantics、stream order 和 memory layout 之间的 cross-layer consistency 被破坏。

---

### 4.2 局部可跑，系统不可部署

每个模块都能仿真，top-level 也能通过简化 testbench，但接入真实 DDR image 和 host runtime 后输出 garbage。

示例：

RTL address generator 假设 weight layout 是 head-major，而 DDR image builder 按 tile-major packing；stage-level 直接喂 tensor trace 时完全正确，但 system-level 从 DDR 读真实 image 后输出错误。

这不是 datapath bug，而是 memory layout、runtime buffer map 和 RTL address trace 不一致。

---

### 4.3 局部优化，全局 QoR 退化

某个 agent 为了优化单个 PU 的 latency 或 resource，改变了 tile size、parallelism 或 FIFO depth，但没有同步更新 downstream consumer 的 stream order、buffer capacity 或 AXI burst pattern，导致全局 pipeline utilization 下降、stall 增加，甚至 deadlock。

这说明 spatial accelerator 的优化不能只看单个 stage，而必须维护跨 stage 的 producer-consumer rate、FIFO occupancy、memory bandwidth 和 layout compatibility。

---

### 4.4 局部修复，引入新 bug

agent 看到 timing violation 后，为了缩短 critical path 在某条 pipeline 上加了一拍 register。但它没有同步调整 valid delay、last signal、residual bypass 或 output strobe，导致数据值对了但 beat alignment 错了。

这说明 backend repair 会反向影响 pipeline semantics。一个修 timing 的 patch 可能破坏 stream protocol 或 model edge semantics。

---

## 5. 为什么已有工作只能解决局部问题？

### 5.1 LLM code generation 工作：解决 local artifact generation，但缺少 global artifact consistency

LLM for RTL/HLS/spec generation 工作主要证明 LLM 可以生成或优化某类硬件 artifact。例如：

* specification；
* HLS kernel；
* Verilog module；
* testbench；
* PPA-aware RTL；
* EDA script；
* decision path。

它们的问题边界通常是局部的。即使采用 multi-agent，也往往围绕 planning、coding、review、evaluation 组织 workflow。它们关注的是“这段 RTL 是否 functional correct / PPA optimized / interpretable”。

但 spatial accelerator design closure 需要回答更复杂的问题：

* 这段 RTL 的 shape assumption 是否和 model config 一致？
* 它的 stream output order 是否和 downstream module read order 一致？
* 它的 scale layout 是否和 DDR image 一致？
* 它的 valid/last timing 是否和 top-level wrapper 一致？
* 它的修复 patch 是否破坏了之前已经通过的 stage/top/system regression？

因此，LLM code generation 工作解决的是 **local artifact quality**，而不是 **global artifact composition consistency**。

---

### 5.2 Accelerator compiler / ADL 工作：解决 structured IR consistency，但不覆盖 agentic heterogeneous artifacts

Allo、StreamTensor 等工作证明，spatial/dataflow accelerator 需要显式 IR、type system、hierarchical dataflow graph、stream layout、FIFO sizing、memory/runtime generation。

这些工作非常重要，因为它们从 compiler 角度证明了：

* multi-kernel composition 不是简单调用 optimized kernels；
* stream order 和 memory layout 必须显式表示；
* producer/consumer rate 必须分析；
* FIFO sizing 不当会导致 stall 或 deadlock；
* local kernel optimization 不保证 global dataflow accelerator 高质量。

但是这些方法主要在结构化 compiler IR 内工作。它们并不直接解决 agentic design 中更广泛的 artifact 一致性问题，例如：

* model document / quantization document；
* Chisel template 参数绑定；
* generated RTL；
* simulation trace；
* DDR image；
* host runtime buffer map；
* Vivado/OpenROAD report；
* repair history；
* human/agent decision log。

SpatialAccAgent 的目标不是替代这些 compiler，而是将它们暴露出的“structured consistency”需求扩展到 agentic design closure 的完整 artifact set。

---

### 5.3 Long-horizon chip agent 工作：证明 feasibility，但缺少可量化的 consistency methodology

Design Conductor 类工作展示了 agent 能完成复杂 chip design flow。这说明 agent 已经不只是写代码，而是开始参与 architecture、implementation、verification、timing closure 和 physical design。

但这类工作更像 impressive case study。它们证明了“agent 可以做出来”，但还没有系统回答：

* 哪些 failure 是跨层一致性错误？
* 哪些 bug 能在 stage-level 被发现，哪些会逃逸到 system-level？
* agent 修复时如何判断 violated constraint 属于 model、numeric、stream、memory、backend 哪一类？
* 如何证明某个 patch 是 minimal repair？
* 如何避免修复一个问题后引入 regression？
* 如何通过 ablation 证明显式 design state 的价值？

因此，SpatialAccAgent 不是再证明一次 agent 能不能设计芯片，而是把 long-horizon agentic accelerator design 中最关键的 design-closure quality 问题形式化、可检查化、可测量化。

---

## 6. 我们发现的核心 gap

综合以上讨论，可以把已有工作的缺口定义为：

**Existing works have made local artifact generation and long-flow execution increasingly feasible. However, deployable LLM spatial accelerator design requires more than local artifact correctness: it requires global consistency across heterogeneous artifacts and evidence. This consistency is currently implicit, fragile, and difficult for agents to maintain or repair.**

中文：

**现有工作已经让局部 artifact 生成和长流程执行逐渐可行。但是，可部署的 LLM spatial accelerator 设计不仅需要局部 artifact 正确，还需要跨 heterogeneous artifacts 和 tool evidence 的全局一致性。目前这种一致性大多是隐式的、脆弱的，并且难以被 agent 稳定维护和修复。**

这个 gap 可以进一步总结为：

**Existing LLM-based hardware agents lack an explicit global design state for cross-stage consistency.**

即：

**现有 LLM 硬件 agent 缺少一个显式的全局设计状态，用来维护跨阶段一致性。**

---

## 7. 为什么这个问题有价值？

论文必须向审稿人证明，这个问题不是自嗨，而是一个真实、严重、普遍、可测量、可解决的问题。建议围绕四个审稿人问题组织证据。

### 7.1 Existence：这个问题真的存在吗？

我们需要证明 cross-layer consistency failure 不是我们凭空想出来的，而是已有领域中反复出现的问题。

前人工作已经从不同角度暴露了这个问题的碎片：

1. Dataflow compiler 工作暴露了 stream layout mismatch、DMA coupling、FIFO sizing、deadlock 等问题；
2. ADL 工作暴露了 optimized kernels 组合后 interface 不兼容、global QoR suboptimal 的问题；
3. LLM accelerator generation 工作暴露了 LLM 容易丢失 long dependencies、误解变量定义、遗漏关键硬件指令；
4. Long-horizon chip agent 工作暴露了 verification、numeric discrepancy、timing closure、backend-vs-RTL repair decision 的高成本问题。

这些问题本质上都指向同一个缺失抽象：

**an explicit, executable design state that spans model semantics, spatial pipeline, hardware artifacts, memory/runtime layout, verification evidence, and backend feedback.**

因此，我们不是创造一个空问题，而是将多个方向都遇到的碎片问题统一抽象为：

**cross-layer consistency problem in agentic LLM spatial accelerator design.**

---

### 7.2 Severity：这个问题是否严重到值得 DAC 论文关注？

这个问题严重，原因有四点。

第一，错误会逃逸到后期。
很多 cross-layer inconsistency 在 stage-level 很难发现，只有 top-level、system-level、board-level 才暴露。一旦错误逃逸到后期，定位成本会急剧增加。

第二，错误症状模糊。
同样的 output mismatch 可能来自 quant scale、stream order、DDR address、softmax approximation、valid alignment 或 GQA mapping。没有显式 constraint state 时，agent 容易 symptom-driven repair，反复猜错层。

第三，修复可能破坏已有正确性。
硬件设计不是软件 patch。一个 timing repair 可能破坏 pipeline alignment；一个 memory layout repair 可能破坏 burst efficiency；一个 numeric repair 可能改变 tolerance envelope。

第四，QoR 会被局部目标误导。
agent 在某个 stage 上优化 latency 或 area，不代表全局 pipeline utilization、DDR bandwidth efficiency、Fmax、resource balance 会改善。spatial accelerator 的 QoR 本质上是跨 stage、cross-artifact 的全局属性。

因此，这不是“小 bug debug”问题，而是 agentic hardware design 从 demo 走向可信设计闭环时必须解决的核心问题。

---

### 7.3 Generality：这是不是某一个项目里的偶然 bug？

必须通过 failure taxonomy 和 fault injection 证明它不是偶然现象，而是一类系统性 failure space。

我们可以将 cross-layer consistency failure 分成以下类别：

1. model / shape mismatch；
2. numeric mismatch；
3. stream order mismatch；
4. missing beat / extra beat；
5. memory-layout mismatch；
6. pipeline-liveness failure；
7. residual / KV / model-edge bug；
8. harness / protocol bug；
9. backend repair bug；
10. timing / resource closure inconsistency。

这些错误不是某一个模型、某一个模板、某一个工具造成的，而是在多层 artifact 转换中普遍可能出现的约束断裂。

为了证明 generality，应在 OPT/GPT-style、LLaMA-style、Qwen-style block 上都观察或注入这些问题，并展示不同模型结构会触发不同类型的一致性风险。例如：

* Qwen-style GQA 更容易暴露 head/KV-head mapping；
* LLaMA-style RoPE 更容易暴露 dimension layout；
* W4A8 更容易暴露 scale/zero-point/packing；
* full dataflow pipeline 更容易暴露 stream/FIFO/liveness；
* DDR/AXI system simulation 更容易暴露 memory/runtime mismatch。

---

### 7.4 Solvability：我们的方法是否真的更好？

我们不能只提出 SACG 概念，还必须证明显式 constraint state 能带来定量改进。

需要证明：

1. 能更早发现错误；
2. 能更准确定位 violated constraint；
3. 能减少 repair iterations；
4. 能减少 human intervention；
5. 能减少 bug escape；
6. 能减少 regression failure；
7. 能提升 design closure success；
8. 能保持 QoR credibility。

因此，实验必须包括：

* motivating study；
* fault injection；
* ablation study；
* end-to-end design closure；
* QoR sanity and competitive performance。

---

## 8. 问题价值证明的四层证据链

论文建议使用四层证据结构证明问题价值。

### 8.1 第一层：Prior-work evidence

目的：证明问题不是凭空创造的。

建议表达：

**Prior works have independently exposed different fragments of the same cross-layer consistency problem. Dataflow compilers observe stream layout mismatch, DMA coupling, and FIFO deadlock. ADLs observe that composing optimized kernels can introduce incompatible interfaces and suboptimal global designs. LLM-based accelerator generation observes that models lose long dependencies across hardware modules. Long-horizon chip agents observe that verification and timing closure dominate cost, and that distinguishing backend fixes from RTL fixes remains difficult. These symptoms point to a common missing abstraction: an explicit, executable design state that spans model semantics, spatial pipeline, hardware artifacts, memory/runtime layout, verification evidence, and backend feedback.**

中文解释：

已有工作分别从 dataflow compiler、ADL、LLM code generation、long-horizon chip agent 的角度暴露了同一个问题的不同碎片。我们的工作不是凭空提出 cross-layer consistency，而是将这些碎片问题统一抽象，并针对 agentic LLM spatial accelerator design 提出可执行、可检查、可修复的 design state。

---

### 8.2 第二层：Motivating study

目的：证明问题在我们目标场景中真实存在、高频出现、代价高。

建议选择 2–3 个 decoder-only LLM block：

* OPT/GPT-2 style；
* LLaMA style；
* Qwen style。

使用几种 baseline flow：

1. 普通 multi-agent flow：planner / coder / verifier，没有 SACG；
2. template-only flow：使用模板，但没有全局 constraint graph；
3. stage-local verification flow：每个 PU 都测，但不做 top/system consistency check；
4. full SpatialAccAgent：使用 SACG + checker + evidence-guided repair。

记录所有自然出现的 failure，并按 taxonomy 分类：

| Failure class        | 典型例子                                     | 证明点                              |
| -------------------- | ---------------------------------------- | -------------------------------- |
| model/shape mismatch | GQA head mapping 错                       | 模型语义会跨层丢失                        |
| numeric mismatch     | W4 scale stride 错                        | 数值策略不是局部 GEMM 问题                 |
| stream mismatch      | producer/consumer tile order 不一致         | stage-level 正确不代表 top-level 正确   |
| beat-count bug       | output 少一拍                               | ready/valid 协议需要全局约束             |
| memory-layout bug    | DDR image 和 RTL address stride 不一致       | system-level artifact 必须和 RTL 绑定 |
| liveness bug         | FIFO depth 不足导致 deadlock                 | pipeline 局部正确不代表全局活性             |
| backend repair bug   | timing fix 加 register 破坏 valid alignment | 后端修复会反向影响流水语义                    |

最有说服力的指标包括：

* total bugs；
* bugs escaping to top/system/board-level；
* average localization iterations；
* human intervention count；
* repair patch size；
* regression failures after repair；
* design closure success rate；
* wall-clock debug time。

目标不是一开始追求完美数字，而是证明：

**多数有价值的失败不是 syntax error，也不是 isolated module bug，而是 cross-layer consistency failure。**

---

### 8.3 第三层：Fault injection

目的：证明问题不是偶然 bug，而是一类可系统测量的 failure space。

可主动注入以下错误：

* GQA KV-head mapping 错；
* RoPE dimension offset 错；
* W4 scale layout 错；
* stream tile order reversal；
* valid 少打一拍；
* FIFO depth 太小；
* residual bypass 接错；
* DDR base address offset 错；
* AXI burst length 错；
* runtime output window size 错；
* timing fix 多加一拍但没改 valid delay。

比较不同方法：

| Method                  | Detection rate | Localization accuracy | Repair success | Avg. iterations |
| ----------------------- | -------------: | --------------------: | -------------: | --------------: |
| log-only agent          |              低 |                     低 |              低 |               高 |
| tests-only agent        |              中 |                   低/中 |              中 |               高 |
| constraint checker only |    高 detection |        中 localization |       无 repair |               - |
| Full SpatialAccAgent    |              高 |                     高 |              高 |               低 |

这组实验的核心作用是证明：

**cross-layer consistency 不是口号，而是可以通过故障空间系统测量的问题。**

---

### 8.4 第四层：Ablation study

目的：证明 SACG 中每一类 constraint 都有价值，不是概念堆砌。

建议逐个移除：

* no shape/model constraint；
* no numeric constraint；
* no stream constraint；
* no beat-count checker；
* no memory constraint；
* no liveness checker；
* no backend/deployment constraint；
* no evidence classifier；
* no repair-log protocol。

观察哪些错误逃逸：

| Removed component         | Expected failure                                |
| ------------------------- | ----------------------------------------------- |
| no shape/model constraint | GQA/RoPE/head mapping bugs 增加                   |
| no numeric constraint     | scale/rounding/saturation mismatch 难定位          |
| no stream constraint      | tile order、head order、lane order 错误逃逸           |
| no beat-count checker     | missing/extra beat 逃逸到 top-level                |
| no memory constraint      | DDR image/runtime/address bugs 逃逸到 system-level |
| no liveness checker       | FIFO deadlock 晚发现                               |
| no backend constraint     | timing repair 引入 pipeline semantic bug          |
| no evidence classifier    | repair iteration 增加，patch 更大                    |
| no repair-log protocol    | regression 不稳定，修复不可审计                           |

这能证明 SACG 不是“把一堆 checker 拼起来”，而是每类 constraint 都对应真实 failure mode。

## 9. 我们的方法为什么正好解决这个问题？

### 9.1 Spatial Accelerator Constraint Graph

我们提出 **Spatial Accelerator Constraint Graph, SACG**，不是普通 operator graph，而是完整 accelerator design package 的显式设计状态。

形式上：

G = (V, E, C, I, A)

含义：

* V：设计实体，包括 model op、processing unit、pipeline stage、memory task、runtime task、verification task、deployment task；
* E：实体关系，包括 stream edge、memory edge、control edge、residual edge、KV-cache edge、deployment edge；
* C：绑定在 node/edge 上的 design constraints；
* I：必须维护的 invariants；
* A：绑定到 graph 的 artifacts，包括 Chisel、RTL、trace、DDR image、testbench、host code、Vivado script、board log。

SACG 的作用不是描述“算了什么”，而是描述：

**这个 accelerator package 中每个 artifact 应该满足哪些跨层约束，以及这些约束如何被检查、传播和修复。**

---

### 9.2 Constraint-state agentic design closure

我们不把 agent 定义成自由代码生成器，而是定义成：

**constraint-state transformer / repairer**

每一步状态为：

S_t = (G_t, A_t, R_t)

其中：

* G_t 是当前 SACG；
* A_t 是当前 artifact set；
* R_t 是当前 evidence / report / log。

每次 agent transition 为：

(G_t, A_t, R_t) -> (G_{t+1}, A_{t+1}, R_{t+1})

每次动作必须回答：

1. 更新了哪个 constraint？
2. 修改了哪个 artifact？
3. 新增了什么 evidence？
4. 哪个 checker 或 regression 支持这个变化？
5. 如果失败，violated constraint 是哪个？
6. 修复 patch 是否最小？
7. 是否通过 regression？

这样，agent 不再是根据自然语言上下文猜测，而是在显式 design state 上做可审计的状态转移。

---

### 9.3 Executable checker suite

为了避免 SACG 变成漂亮 schema，必须配套可执行 checker：

* sacc-lint：检查 shape/model/numeric 基本一致性；
* stream-trace-check：检查 producer/consumer stream order；
* beat-count-check：检查 valid-ready transaction 数量、missing beat、extra beat；
* addr-map-check：检查 DDR image、runtime config、RTL address trace 是否一致；
* numeric-compare：检查 stage/top 输出是否满足 numeric tolerance；
* deadlock-watchdog：检查 FIFO occupancy、valid-ready stall、bounded liveness；
* repair-log-check：检查每次 repair 是否完整记录 symptom -> evidence -> violated_constraint -> patch -> regression_result。

这些 checker 的目标不是替代仿真，而是把仿真和工具日志转化为 constraint-level evidence。

---

### 9.4 Evidence-guided constraint repair

传统 agent 修复往往是 symptom-driven：

* 看到 output mismatch，就猜 softmax；
* 看到 timing violation，就大改 RTL；
* 看到 system output garbage，就怀疑 datapath；
* 看到 numeric mismatch，就放宽 tolerance。

SpatialAccAgent 的修复逻辑应该是：

symptom -> evidence -> violated constraint -> minimal patch -> regression result

例如：

* output 少一拍 -> beat-count trace 显示 missing final beat -> violated beat-count constraint -> 修 valid/last gating -> regression；
* system-level output garbage -> addr trace 与 DDR image layout 不一致 -> violated memory constraint -> 修 address stride 或 image packing -> regression；
* W4 output systematic bias -> scale read stride 与 scale packing 不一致 -> violated numeric/memory constraint -> 修 scale layout -> regression；
* timing fix 后 top-level mismatch -> added register broke valid alignment -> violated pipeline/stream constraint -> 修 valid delay and residual bypass -> regression。

这就是 evidence-guided repair 的核心价值。

## 11. Introduction 中建议采用的叙事逻辑

### 第一段：Feasibility has arrived

LLM for hardware 已经从 specification / RTL / HLS generation 走向 PPA-aware RTL optimization、multi-agent RTL design、EDA tool automation 和 long-horizon chip design。这说明 agent 参与硬件设计已经不是遥远设想。

### 第二段：But usability is not guaranteed

真实 LLM spatial accelerator 不是一个 RTL 文件，而是一组高度耦合的 artifact。局部 artifact 可以单独正确，但组合后可能出现 model semantics、numeric policy、stream protocol、memory layout、runtime configuration、backend assumptions 之间的不一致。

SpatialAccAgent 提出 Spatial Accelerator Constraint Graph，将 design constraints、invariants、artifacts 和 evidence 显式绑定；agent 作为 constraint-state transformer / repairer 运行；checker 将 artifact 和 constraint 对齐；repair loop 将 tool evidence 映射为 violated constraint 并执行 minimal repair。

通过 prior-work evidence、motivating study、fault injection、ablation 和 end-to-end closure 证明：

1. 问题真实存在；
2. 问题代价高；
3. 问题不是偶然个例；
4. 我们的方法能降低 bug escape、repair iterations、human intervention，并提高 design closure success 和 QoR credibility。

## 12. 可以直接写进论文的 Problem Definition 段落

**Problem Definition Draft**

We target the cross-layer consistency problem in agentic LLM spatial accelerator design. A decoder-only Transformer block must be transformed through a heterogeneous sequence of representations and artifacts, including model configurations, operator semantics, quantization policies, spatial pipeline plans, Chisel/RTL modules, stream interconnects, DDR/AXI layouts, host runtime code, verification traces, and backend implementation reports. Although an LLM agent may generate locally valid artifacts at each stage, these artifacts must preserve shared assumptions about tensor shapes, attention-head mapping, numerical formats, stream order, memory packing, pipeline liveness, and deployment interfaces. When such assumptions are implicit, locally correct artifacts can compose into globally incorrect, undeployable, or QoR-degraded accelerators.

Existing LLM-based hardware design systems mainly improve local artifact generation, RTL optimization, EDA tool scripting, or long-horizon flow execution. Existing accelerator compilers and ADLs provide structured IRs and type systems for kernel composition, stream layout, and dataflow optimization. However, agentic accelerator design requires a broader explicit design state that links heterogeneous specifications, hardware templates, generated RTL/Chisel, traces, DDR images, runtime configurations, tool reports, and repair history. Without such a state, an agent can observe symptoms such as output mismatch, missing beats, deadlocks, wrong addresses, numeric discrepancies, or timing violations, but cannot reliably determine which cross-layer constraint was violated or how to produce a minimal, regression-safe repair.

SpatialAccAgent addresses this problem by introducing a Spatial Accelerator Constraint Graph and a constraint-guided agentic design-closure flow. Rather than treating agents as unconstrained code generators, SpatialAccAgent treats them as constraint-state transformers and repairers. Each agent action updates the explicit design state, generates or modifies artifacts, collects tool evidence, invokes executable checkers, and maps failures to violated constraints for evidence-guided repair.

## 13. 可以直接写进论文的 Problem Value 段落

**Problem Value Draft**

This problem is important for three reasons. First, prior work has independently exposed different fragments of the same issue. Dataflow compilers show that stream layout mismatch, DMA coupling, and FIFO sizing can break correctness or performance. ADLs show that composing optimized kernels can introduce incompatible interfaces and suboptimal global designs. LLM-based accelerator generation shows that current models lose long dependencies and overlook hardware-specific instructions. Long-horizon chip agents show that verification, numeric discrepancy analysis, timing closure, and backend-vs-RTL repair decisions dominate design effort. These observations suggest that the bottleneck is shifting from generating individual hardware artifacts to maintaining a consistent design state across artifacts.

Second, cross-layer consistency failures are costly because they often escape local verification. A processing unit may pass stage-level tests, while the full accelerator fails due to a stream-order mismatch, wrong DDR packing rule, misaligned valid signal, incorrect scale stride, or backend timing repair that breaks pipeline semantics. Such failures are difficult to localize from raw simulation logs or EDA reports because the same symptom may arise from different design layers.

Third, the problem is measurable and actionable. By classifying failures into model/shape, numeric, stream, beat-count, memory-layout, liveness, deployment, and backend-repair categories, we can quantify bug escape rates, localization iterations, repair patch sizes, regression failures, and human intervention. This enables a rigorous evaluation of whether an explicit constraint state improves agentic design closure beyond ordinary multi-agent prompting, template-based generation, or stage-local verification.
