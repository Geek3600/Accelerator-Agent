先把这件事收敛成一句话：

**我们要先证明：Cross-Layer Consistency 不是我们自己造出来的问题，而是前人工作已经在不同场景中反复遇到的真实问题；然后再进一步证明：当这个问题进入 LLM agent 长流程设计时，会被放大成 consistency drift，也就是 agent 在多轮局部修复中逐渐让设计偏离正确路径。**

下面这份文档是正式版规划。文档里的英文尽量使用常见词。文献依据可对应到：StreamTensor 明确讨论 inter-kernel、stream layout、FIFO、DMA、runtime 等问题，并指出传统 tensor type 不能保证 dataflow communication 正确性；Allo 强调 single-kernel 到 multi-kernel design 的组合问题和 type-safe composition；GPT4AIGChip 明确列出 LLM 在 AI accelerator design 中的 variable misunderstanding、long dependency、missed instruction 等失败；Design Conductor 2.0 展示 long-flow agent 可行，但同时暴露 numeric debug 和 timing closure 的高成本。      

# 如何证明 Cross-Layer Consistency Problem 存在：文献证据与实验规划文档

## 0. 文档目的

本文档用于规划 SpatialAccAgent 论文中“问题存在性”的证明逻辑。

当前论文定义的问题是：

**Cross-Layer Consistency Problem in Agentic LLM Spatial Accelerator Design**

中文含义是：

**面向 agentic LLM spatial accelerator 设计的跨层一致性问题。**

我们不能一开始就直接说 LLM agent 会导致设计漂移。这个说法成立的前提是：Cross-Layer Consistency Problem 本身已经在前人硬件设计、加速器编译、dataflow accelerator、LLM hardware agent 和 long-flow chip agent 工作中真实存在。

因此，证明逻辑必须分两层：

1. **第一层：证明 Cross-Layer Consistency Problem 在前人工作中已经存在。**
2. **第二层：证明这个问题放到 LLM agent 长流程设计中会被放大，形成 Consistency Drift。**

本文档重点规划第一层，同时说明如何自然过渡到第二层。

---

## 1. 核心结论

我们要向审稿人证明的不是：

**前人工作已经明确提出了 Cross-Layer Consistency 这个名字。**

因为多数前人工作不会使用这个术语。

我们要证明的是：

**前人工作虽然没有统一命名，但它们已经在不同层面反复暴露出同一类问题：局部正确不代表全局正确，单个 design file 正确不代表完整 accelerator package 可以闭环。**

更正式地说：

**Cross-layer consistency is a hidden but common problem in prior accelerator and chip design work. It appears under different names, such as multi-kernel composition, stream layout mismatch, FIFO sizing, memory layout, long dependency, verification, timing closure, and tool feedback.**

中文：

**跨层一致性是前人加速器和芯片设计工作中已经反复暴露的隐藏问题。它在不同论文中使用不同名字出现，例如 multi-kernel composition、stream layout mismatch、FIFO sizing、memory layout、long dependency、verification、timing closure 和 tool feedback。**

---

## 2. 我们为什么必须先证明第一层问题？

如果不先证明 Cross-Layer Consistency Problem 本身存在，那么后面关于 LLM agent 的论证就会显得没有根基。

审稿人会问：

1. 这是 spatial accelerator 设计中真实存在的问题吗？
2. 还是你们为了提出 SACG 而人为构造的问题？
3. 如果没有 LLM agent，人类或 compiler 是否已经解决了它？
4. 为什么需要一个新的 design state？

因此，第一层证明的目标是：

**证明 Cross-Layer Consistency Problem 是一个已有设计流程中真实存在、反复出现、但没有被统一解决的问题。**

只有这个成立，第二层才能继续说：

**LLM agent 会进一步放大这个问题。**

---

## 3. 第一层问题的定义

在传统 spatial accelerator 或 dataflow accelerator 设计中，一个完整 accelerator 不是单个 kernel、单个 RTL module 或单个 script，而是多个 design files 和 tool results 组成的系统。

这些内容包括：

* model semantics；
* operator graph；
* multi-kernel schedule；
* stream order；
* FIFO depth；
* memory layout；
* DMA / DDR access；
* host runtime；
* RTL / Chisel；
* testbench；
* verification trace；
* synthesis report；
* timing report；
* board result。

这些对象之间存在共享假设。例如：

* producer 和 consumer 的 stream order 必须一致；
* kernel fusion 后的 layout 必须和 buffer/FIFO 匹配；
* memory packing 必须和 address generator 匹配；
* local kernel optimization 不能破坏 global dataflow；
* timing fix 不能破坏 pipeline valid alignment；
* runtime buffer map 必须和 hardware address map 一致。

当这些共享假设没有显式维护时，就会出现 Cross-Layer Consistency Problem。

---

## 4. 第一层证明的总体方法

建议采用：

**Prior-Work Evidence Study**

中文可以叫：

**前人工作证据分析**

这不是自定义实验指标，也不是主观叙述，而是一种系统文献整理方法。

基本做法是：

1. 选择一批相关工作；
2. 将它们分成若干类别；
3. 对每篇工作标注它暴露了哪类 consistency 相关问题；
4. 统计不同类别问题在前人工作中的出现情况；
5. 总结：前人工作已经分别暴露了 Cross-Layer Consistency 的不同局部形态，但没有提供一个统一的全局设计状态来覆盖 agentic LLM spatial accelerator design。

## 7. 如何量化第一层问题存在？

不要发明复杂指标。使用最简单的：

**counts and percentages**

也就是统计数量和比例。

### 7.1 统计方式

假设我们阅读 N 篇相关工作，可以报告：

* 有多少篇报告 local-to-global issue；
* 有多少篇报告 stream/memory issue；
* 有多少篇报告 long-context issue；
* 有多少篇报告 verification/closure issue；
* 有多少篇使用显式 state；
* 有多少篇覆盖 model-to-backend 全链路；
* 有多少篇记录 repair history；
* 有多少篇提供 checker-based state update。

示例写法：

**We reviewed N prior works across four groups: ADL/compiler, dataflow compiler, LLM hardware agent, and long-flow chip agent. Among them, X works report local-to-global composition issues, Y works report stream or memory issues, Z works report long-context failures in LLM-based design, and W works report verification or closure issues. However, none of them provides a single explicit design state that links model semantics, spatial pipeline, Chisel/RTL files, stream traces, DDR/runtime layout, backend reports, and repair history.**

中文：

**我们整理了 N 篇相关工作，覆盖 ADL/compiler、dataflow compiler、LLM hardware agent 和 long-flow chip agent 四类。其中，X 篇报告了 local-to-global composition 问题，Y 篇报告了 stream 或 memory 问题，Z 篇报告了 LLM-based design 中的 long-context failure，W 篇报告了 verification 或 closure 问题。但没有工作提供一个显式设计状态，同时连接 model semantics、spatial pipeline、Chisel/RTL、stream trace、DDR/runtime layout、backend report 和 repair history。**

---

### 7.2 这类量化为什么可信？

这种量化不是我们发明的新性能指标，而是文献综述中常见的 evidence coding。

它的可信性来自：

1. 每个 yes/no 标注都能回到原文证据；
2. 分类规则提前定义；
3. 覆盖多类相关工作；
4. 统计结果只用于证明问题存在，不用于夸大方法效果；
5. 表中也明确承认前人已经解决了局部问题。

## 8. 第一层证明的预期结论

通过 prior-work evidence study，我们希望得出以下结论：

### 8.1 结论 1：Cross-Layer Consistency Problem 不是新造概念

前人工作虽然没有统一使用 cross-layer consistency 这个词，但它们已经在不同层面反复暴露了相同问题：

* kernel composition；
* stream layout；
* FIFO sizing；
* memory layout；
* long dependency；
* verification；
* timing closure；
* backend feedback。

这说明该问题真实存在。

---

### 8.2 结论 2：前人解决的是局部一致性，不是全局设计状态

不同工作有各自的 state：

* Allo 使用 type system / IR；
* StreamTensor 使用 stream type / dataflow IR；
* GPT4AIGChip 使用 template / prompt；
* ChatEDA 使用 task list / tool script；
* Design Conductor 使用 memory / logs。

但这些 state 多数只覆盖自身范围：

* compiler IR 内部；
* HLS/RTL code；
* stream/dataflow；
* EDA tool script；
* chip-agent memory。

它们没有提供一个统一状态，覆盖：

* model semantics；
* spatial pipeline；
* Chisel/RTL；
* stream trace；
* DDR image；
* runtime config；
* verification result；
* backend report；
* repair history。

---

### 8.3 结论 3：这为 SACG 提供了必要性

SACG 的必要性不是因为前人没有自动化，而是因为前人的自动化仍然缺少一个贯穿全流程的设计状态。

因此，SACG 的位置是：

**not a replacement for compiler IR, but a design state for agentic design closure**

中文：

**SACG 不是替代 compiler IR，而是为 agentic design closure 提供全局设计状态。**

---

## 9. 第二层问题：LLM Agent 会放大 Cross-Layer Consistency Problem

第一层证明完成后，可以自然引入第二层问题。

### 9.1 第二层问题的定义

在传统 accelerator design 中，cross-layer consistency 已经很难。但人类工程师通常会通过经验和设计文档维持全局设计意图。

在 LLM agent 长流程设计中，问题会更严重，因为 agent：

* 没有天然稳定的全局设计状态；
* 容易忘记早期设计假设；
* 可能根据最新 log 做局部修复；
* 可能修错层；
* 可能给出听起来合理但错误的解释；
* 可能为了让当前 test 通过而破坏其他 test；
* 可能反复修改多个文件，使设计逐渐偏离目标。

这可以称为：

**Consistency Drift**

中文：

**一致性漂移**

---

### 9.2 Consistency Drift 的正式定义

**Consistency Drift means that, during a long agentic design flow, local repairs gradually move the design away from the intended model, pipeline, stream, memory, and runtime assumptions. Each patch may look reasonable by itself, but the accumulated changes make the full accelerator less consistent and harder to repair.**

中文：

**一致性漂移是指在长流程 agentic design 中，局部修复逐渐让设计偏离原本的模型、pipeline、stream、memory 和 runtime 假设。每个 patch 单独看似合理，但累积起来会让完整 accelerator 越来越不一致，也越来越难修复。**

---

### 9.3 第二层问题和第一层问题的关系

两者关系是：

**Cross-Layer Consistency Problem 是底层问题。**

**Consistency Drift 是该问题在 LLM agent 长流程设计中被放大后的表现。**

也就是说：

* 如果没有 cross-layer consistency problem，就谈不上 consistency drift；
* 如果没有 LLM agent 的多轮自动修改，cross-layer consistency 只是传统设计中的 debug 难点；
* 当二者结合时，agent 可能在没有全局设计状态的情况下越修越偏。

---

## 10. 如何证明第二层问题？

第二层问题不能只靠讨论 LLM hallucination。必须用设计行为证明。

建议使用：

**Repair Drift Study**

中文：

**修复漂移实验**

### 10.1 实验目标

证明 plain agent 在处理 cross-layer failure 时更容易出现：

* wrong-layer repair；
* regression break；
* larger patch；
* more repair attempts；
* broken constraints increase over rounds；
* manual code edit increase。

而 SpatialAccAgent 通过 SACG + checker + regression gate 可以减少这些问题。

---

### 10.2 需要记录的行为

对于同一个 failure event，记录每一轮 agent 修复：

* root cause guess；
* modified files；
* changed lines；
* changed constraints；
* checker result；
* regression result；
* whether repair is on correct layer；
* whether new failure appears。

---

### 10.3 可使用的标准指标

使用常见指标，不发明新指标：

* Top-1 root cause accuracy；
* Top-3 root cause accuracy；
* repair success rate；
* regression pass rate；
* number of repair attempts；
* changed files；
* changed lines；
* time-to-fix；
* manual code edits；
* number of broken constraints after each round。

其中 number of broken constraints 是简单计数，不是复杂自定义指标。

---

**In LLM agent design, this fragmented problem becomes more severe because agent repair is long, local, and log-driven.**

在自己的 accelerator design events 上比较 plain agent 和 SpatialAccAgent。

## 14. 最终可写入论文的段落

### 14.1 Problem Existence Paragraph

**To show that cross-layer consistency is not an artificial problem, we first conduct a prior-work evidence study. We review prior work in ADL/compiler, dataflow compiler, LLM-based hardware agents, and long-flow chip agents. These works repeatedly expose different parts of the same problem: local kernels do not automatically compose into a correct global accelerator; stream layout and FIFO sizing must be explicitly managed; LLMs lose long design dependencies; and long-flow chip agents spend large effort on verification, numeric debug, and timing closure. However, these solutions remain local to compiler IRs, stream types, templates, prompts, task lists, or tool logs. They do not provide a single design state that links model semantics, spatial pipelines, Chisel/RTL files, stream traces, DDR/runtime layouts, backend reports, and repair history.**

---

### 14.2 Consistency Drift Paragraph

**This problem becomes more severe in LLM-agent design. Without an explicit design state, an agent may enter a log-driven repair loop: it repeatedly modifies local files based on the latest error message while losing track of earlier model, stream, memory, or pipeline assumptions. Each patch may look reasonable in isolation, but the accumulated changes can move the design away from the intended accelerator behavior. We call this failure mode consistency drift. SpatialAccAgent prevents this drift by maintaining an explicit constraint state and accepting a repair only when checkers and regression show that the global design remains consistent.**

## 15. 最终总结

本文档给出的证明路线是：

1. **先证明 Cross-Layer Consistency Problem 在前人工作中存在。**

   * 用 prior-work evidence map；
   * 用 counts and percentages；
   * 用原文证据支持每个标注。

2. **再证明 LLM agent 会放大这个问题。**

   * 引入 Consistency Drift；
   * 用 repair drift study 证明 plain agent 会修错层、破坏 regression、让 broken constraints 增加。

3. **最后引出 SpatialAccAgent。**

   * SACG 提供显式设计状态；
   * checker 发现 broken constraints；
   * bounded repair 防止局部修复导致全局漂移；
   * regression gate 保证修复不破坏已有正确性。

这条路线可以直接回答审稿人的核心质疑：

**Cross-Layer Consistency 不是我们自己编出来的问题；它已经在前人工作中反复出现。LLM agent 只是让这个问题更严重，而 SpatialAccAgent 的价值就是让这个问题变得可见、可检查、可修复。**
